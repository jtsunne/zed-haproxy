# HAProxy Zed Extension — Roadmap

Long-range plan for the extension's capabilities. Tier 1 (editor UX: semantic highlighting, folding, outline) shipped as v0.2.0. Tier 2 (editing intelligence: completion, hover, references, rename, stick-table symbol kind) shipped as v0.3.0 — see [`plans/completed/2026-04-18-tier2-editing-intelligence.md`](plans/completed/2026-04-18-tier2-editing-intelligence.md). Tier 3 (diagnostics + multi-file resolution + workspace symbols) shipped as v0.4.0 — see [`plans/completed/2026-04-19-tier3-diagnostics-multifile.md`](plans/completed/2026-04-19-tier3-diagnostics-multifile.md).

## Current state (v0.4.x)

- Semantic syntax highlighting (directives colored by category)
- Go to Definition / Declaration, cursor-aware, across backend/frontend/listen/ACL/server/stick-table; cross-file when a project root is discovered
- Folding (sections, comment banners, BEGIN/END markers)
- Document outline + breadcrumbs
- Find References (`textDocument/references`) with `includeDeclaration` handling, cross-file
- Rename (`textDocument/rename` with `prepareProvider`) for backends, ACLs, servers, frontends, listens; `WorkspaceEdit` spans every affected file
- Hover (`textDocument/hover`) for backends, ACLs, stick-tables, servers, and ~50 curated directive docs
- Completion (`textDocument/completion`) for backends, ACLs, servers, stick-tables, and per-section directive allowlists — ranked by in-file usage frequency
- Diagnostics (`textDocument/publishDiagnostics`): 8 rules covering undefined/unused/duplicate references and missing `default_backend` (Tier 3.1)
- Cross-file resolution: follows `.include` / `.if`-`.endif` / `-f` / `crt` references; opt-in via `.zed/haproxy.toml`
- Workspace symbols (`workspace/symbol`) for `Cmd+T` project-wide fuzzy search
- Regex-based parser in the LSP

## Tier 1 — Editor UX (shipped as v0.2.0)

Semantic highlighting, LSP foldingRange, LSP documentSymbol.

## Tier 2 — Editing intelligence (shipped as v0.3.0)

**Goal:** make the extension actively helpful while typing, not just correct while reading. After Tier 2 the user spends less time typing symbol names and less time jumping around to remember what a reference points at.

### 2.1 Completion (`textDocument/completion`)

Context-sensitive identifier completion. Trigger on space/typing after these tokens:

| After token | Complete | Source |
|---|---|---|
| `use_backend`, `default_backend` | Backend names | `self.symbols[uri]` kind=Backend |
| `if`, `unless`, `!` | ACL names | kind=Acl |
| `use_server` | Server names in the enclosing backend | kind=Server scoped to parent |
| `sc0_gpc0_rate(`, `sc0_inc_gpc0(`, `sc1_*`, `stick match` | Stick-table names | kind=StickTable (new) |
| Start of line inside a section | Valid directives for that section | hard-coded per-section allowlist |

Completion items include `detail` (e.g. the backend's balance algorithm) and `documentation` (brief HAProxy doc snippet). Rank by frequency of use in the current file.

Advertise `completionProvider` with `triggerCharacters: [" ", "("]` in init capabilities.

### 2.2 Hover (`textDocument/hover`)

Rich hover content keyed on the token under the cursor:

- **Over `use_backend X`** → the definition line of backend X plus its server list (up to 5, truncate with "…N more"), balance algorithm, mode.
- **Over an ACL name in a condition** → the ACL's definition line.
- **Over a directive name** → a brief HAProxy docs snippet from a bundled table (`directive → one-paragraph description + syntax + common flags`). Snippet table lives in `src/docs.rs` as a `HashMap<&'static str, &'static str>`; keep it curated, not autogenerated — ~50 entries covers 90% of what gets hovered.
- **Over a server address** → formatted `host:port` plus any relevant flags (`check`, `backup`, `weight N`).

Advertise `hoverProvider: true`.

### 2.3 Find References (`textDocument/references`)

Complement to the existing `textDocument/declaration`. Cursor on a definition → return every call-site in the current file as `Location[]`. Trivial given the existing `references` field on `Symbol` — just wire up the LSP handler.

Advertise `referencesProvider: true`.

### 2.4 Rename (`textDocument/rename`)

Safe single-file rename of backends, ACLs, servers, and frontends/listens (frontends less critical but cheap to include). Returns a `WorkspaceEdit` with `TextEdit`s for the definition plus every reference.

Client-side flow:
1. User invokes rename on a symbol.
2. LSP returns `prepareRename` with the exact range of the identifier token.
3. User types the new name.
4. LSP returns `WorkspaceEdit` covering definition + references.

Advertise `renameProvider: { prepareProvider: true }`.

### 2.5 Tier 2 acceptance

- Completion suggests ≥5 backend names within a `use_backend ` prefix on `test/haproxy.cfg`.
- Hover on `use_backend opcart-direct` shows the backend's servers and mode.
- Rename of `opcart-direct` updates all call-sites in the file in one atomic edit.

### 2.6 Tier 2 test coverage

Extend `test/lsp_probes.py` with:
- Completion probes asserting candidate lists per context
- Hover probes asserting returned `MarkupContent` includes expected strings
- References probes asserting the `declaration` fix still works plus new `references` handler
- Rename probes asserting `WorkspaceEdit` covers definition + all references

## Tier 3 — Diagnostics & multi-file (shipped as v0.4.0)

**Goal:** catch typos and dead code before the user runs `haproxy -c`, and make the extension useful for projects with fragmented configs. This is where the extension becomes opinionated — it starts telling the user things are wrong.

### 3.1 Diagnostics (`textDocument/publishDiagnostics`)

Pure static analysis, runs on every `didOpen`/`didChange`:

| Rule | Severity | Example |
|---|---|---|
| Reference to undefined backend | Error | `use_backend nope` when no `backend nope` exists |
| Reference to undefined ACL | Error | `use_backend foo if undefined_acl` |
| Reference to undefined server in `use_server` | Error | `use_server nope if …` |
| Unused backend | Warning | `backend orphan` never referenced |
| Unused ACL | Warning | `acl orphan src 1.2.3.4` never referenced |
| Duplicate section name | Error | two `backend foo` sections |
| Duplicate ACL in same frontend/listen | Error | two `acl foo …` in one section |
| Missing `default_backend` in a frontend that has `bind` but no `use_backend` | Warning | likely a misconfig |

Diagnostics are pushed proactively (LSP notification), not pulled. No `diagnosticProvider` capability needed — `publishDiagnostics` is server-initiated.

### 3.2 Cross-file resolution

**Trigger**: HAProxy configs in deployed environments typically split across files. Two idioms:

- Explicit: HAProxy 2.8+ supports `.if` / `.include` preprocessor directives. We detect and follow these.
- Implicit: `src -f /etc/haproxy/trusted.cfg`, `bind … crt /etc/ssl/haproxy/cert.pem`, external files referenced via the `-f` flag on various directives.

**Implementation**:

1. On `didOpen` of any HAProxy file, run a project-root discovery: walk up the worktree looking for `haproxy.cfg`, then parse its `include`/`-f` references recursively to build a dependency graph.
2. Index all backends, ACLs, servers, frontends across the graph. `symbols`, `folds`, `outline`, `documents` caches gain a URI key per file.
3. `textDocument/definition` and `references` consult the cross-file index, not just the current file.
4. `-f <path>` references themselves become navigable: F12 on the path jumps to the file.

**Opt-in**: configurable via LSP initialization options or an `.zed/haproxy.toml` project config:

```toml
[haproxy]
project_root = "/etc/haproxy"     # or relative to worktree
follow_includes = true
extra_files = ["conf.d/*.cfg"]
```

### 3.3 Workspace symbols (`workspace/symbol`)

Once cross-file indexing is in place, `workspace/symbol` is ~20 lines: enumerate every symbol in every indexed file, filter by query string, return `SymbolInformation[]`. Zed uses this for `Cmd+T` project-wide symbol search.

Advertise `workspaceSymbolProvider: true`.

### 3.4 Tier 3 acceptance

- A fresh `use_backend undefined_backend` line shows a red underline within 200ms.
- Cross-file index discovers at least one linked file from `test/haproxy.cfg` (add a fixture with `-f` reference).
- `Cmd+T` searching `opcart` lists `backend opcart-direct` from any file in the project.

## Tier 4 — Polish & tree-sitter migration

**Goal:** clean up the rough edges and replace the fragile regex parser with a real AST. After Tier 4 the LSP is production-quality maintainable.

### 4.1 Code actions (`textDocument/codeAction`)

Quick-fixes attached to diagnostics:

- **"Create backend `X`"** on an "undefined backend" diagnostic — inserts a skeleton `backend X\n    mode http\n    balance roundrobin\n` at the end of the file.
- **"Create ACL `X`"** on an "undefined ACL" diagnostic — prompts for the criterion and inserts at the top of the enclosing frontend.
- **"Remove unused backend"** on unused-backend warnings — deletes the section range.
- **"Extract inline ACL"** — given `use_backend X if { path_beg /api }`, pulls the anonymous criterion into a named `acl` definition.

Advertise `codeActionProvider: { resolveProvider: true }`.

### 4.2 Snippets

Ship as Zed snippet files (or via completion `InsertText` with `SnippetString` format):

- `https-redirect`: full HTTPS-redirect frontend with HSTS headers
- `rate-limit`: stick-table + ACL + `tcp-request content` rate-limit pattern
- `backend-checked`: backend with `server` + HTTP health check
- `resolvers-aws`: AWS VPC DNS resolvers block
- `stats-dashboard`: `listen stats` block with auth and prometheus exporter

### 4.3 Formatting (`textDocument/formatting`)

HAProxy configs have no official formatter. Opinionated rules:

- Column-align `server name address [options]` within a backend (name col, address col, options col).
- Column-align `timeout T V` where multiple `timeout` directives cluster.
- Normalize indentation to 4 spaces (current community convention).
- Preserve blank-line separation between sections; collapse runs of 3+ blank lines to 2.
- Do NOT reorder directives — only whitespace.

Opt-in via Zed's `format_on_save` setting per-language. Advertise `documentFormattingProvider: true`, no range-formatter (too risky for a whitespace-sensitive config format).

### 4.4 Tree-sitter migration

The single biggest refactor in Tier 4. Current state:

- Grammar (`Ziehnert/tree-sitter-haproxy`) is loaded in Zed for highlighting.
- LSP (`src/lsp_server.rs`) has a `tree_sitter::Parser` field but never uses it — all parsing is regex.

**Migration plan**:

1. Add `tree-sitter-haproxy` as a Rust crate dependency (the grammar ships a Rust binding; pin the same commit as `extension.toml`).
2. In `HaproxyLsp::new`, `parser.set_language(tree_sitter_haproxy::LANGUAGE.into())?`.
3. Replace `parse_document`'s line-scanning logic with tree-sitter queries:
   - Keep the same output shape (`symbols`, `folds`, `outline`, `documents` caches) — downstream handlers don't need to change.
   - Write `.scm` query files mirroring the regex logic: section extraction, ACL/backend/server definitions, `use_backend`/`default_backend`/condition references.
   - Store queries as `include_str!(…)` constants, compile once at startup.
4. Drop all regex code paths, remove the `regex` crate from the feature set.

**Wins**:
- Proper scope awareness: an `acl foo` inside one frontend doesn't collide with `acl foo` in another when we later add frontend-scoped ACL resolution.
- Robust to multi-line directives and weird whitespace.
- Errors in the input don't corrupt the symbol table (tree-sitter error recovery).
- Aligns LSP with the highlighter — both speak the same AST.

**Risks**:
- Compiled grammar size (+~200 KB binary).
- Binding ergonomics are awkward (raw `TSNode`/`Query` API); consider adding small helper wrappers.
- Incremental reparse support requires careful `InputEdit` tracking on `didChange` — the naive full-reparse is fine for a ~1200-line config, defer incremental to a follow-up.

### 4.5 Tier 4 acceptance

- Quick-fix "Create backend X" creates a working skeleton that resolves the diagnostic.
- `format on save` aligns `server` lines in `test/haproxy.cfg` consistently.
- Tree-sitter migration lands with all Tier 1/2/3 LSP probes still passing (zero behavioral regression).

## Tier 5 — Advanced (stretch)

Out of near-term scope, but worth writing down so they don't get re-invented later.

### 5.1 `haproxy -c -f` integration

On save, spawn `haproxy -c -f <file>` (configurable path, default `haproxy` on PATH). Parse the stderr output (format: `[ALERT] (pid) : parsing [file:line] : reason`) and publish as `Diagnostic` entries alongside the static ones from Tier 3.1. Gated behind a config flag — not everyone has `haproxy` installed locally.

### 5.2 Version-aware directive validity

HAProxy directives come and go between versions (e.g. `nbproc` deprecated in 2.5, `fc_rtt` added in 2.6, `.if`/`.include` added in 2.8). Maintain a `HashMap<directive, VersionRange>` table keyed by directive name. Surface as:

- Diagnostic when a directive is used outside its valid range (configurable target version).
- Hover annotation "since 2.4, deprecated in 2.5".

Source of truth: HAProxy's own `doc/configuration.txt` — scrape into a JSON file at build time, not hand-maintained.

### 5.3 Inlay hints (`textDocument/inlayHint`)

Show resolved values inline without modifying the file:

- Next to `use_backend X`, show `→ server1:80, server2:80` (resolved target endpoints).
- Next to `sc0_gpc0_rate() gt 10`, show the actual value over the current measurement window (from a connected HAProxy instance — stretch).
- Next to a `server` line referencing a health-check, show the check URL.

Advertise `inlayHintProvider: true`.

### 5.4 Live stats integration

Far-future: optionally connect to a running HAProxy's Runtime API (via UNIX socket or HTTP) to pull live backend health status and show it in the outline (green dot = all servers up, yellow = partial, red = all down). Requires trust configuration, not a default-on feature.

## Versioning cadence

- **v0.2.0** — Tier 1 ships (editor UX)
- **v0.3.0** — Tier 2 ships (editing intelligence)
- **v0.4.0** — Tier 3 ships (diagnostics + multi-file)
- **v0.5.0** — Tier 4 ships (code actions + tree-sitter)
- **v1.0.0** — Tier 4 settled, docs complete, marketplace-ready release
- **v1.x** — Tier 5 features as opt-in additions

Each tier is independently shippable and independently useful. A user who stops adopting after Tier 2 still has a materially better extension than today.

## Non-goals

- Not a config templating engine. `haproxy.cfg.j2` is out of scope.
- Not a config generator. No UI for building configs interactively.
- Not a deployment tool. Reloading HAProxy is the user's operational concern.
- Not multi-language (HAProxy Data Plane API, Lua scripts, SPOE agents all out of scope — an HAProxy config file is the unit of work).
